# 音频处理策略与对照实验

核对日期：2026-09-18。范围：IND-53 的产品策略与实验设计；未录音、未调用付费接口、未测得效果数据。

## 当前决定

保留现有采集路径：Speaker 不主动请求 Apple Voice Processing，不接入额外降噪库。先确认实际问题，再用对照数据决定是否改变默认值。本轮 beta 不以新增音频处理能力为发布前提，发布判断见[语音输入发布验收](voice-input-release-acceptance.md)。

这里的 raw 指“Speaker 不主动增加语音处理”，不承诺麦克风硬件、驱动或系统完全没有处理。当前实现绑定本次冻结的设备，随后创建转换器，将音频转为 16 kHz、16-bit、单声道 PCM；启动后记录 Voice Processing、AGC、系统首选和实际麦克风模式。[采集实现](../../Sources/SpeakerCore/VoiceInput/LiveVoiceInputAdapters.swift) [当前规范](../specs/voice-input.md)

[既有办公噪声调研](office-noise-and-competing-speech.md)中的“默认尝试启用 Apple Voice Processing”描述已过时；当前行为以代码、规范与本策略为准。它对候选技术的研究可作为后续选型输入，不能视为已启用或已验证的能力。

## 先区分问题

| 问题 | 评估方向 | 不能据此承诺 |
| --- | --- | --- |
| 风扇、空调等稳定噪声；键盘等瞬态噪声 | 首先比较近讲/耳麦与现有路径；必要时评估系统噪声抑制 | 听起来更安静，不等于识别更准确 |
| 本机扬声器回声 | 评估能获得正确播放参考的回声消除路径；耳机作为对照 | 不能把旁人讲话当成有参考信号的回声 |
| 房间混响 | 先比较距离、摆位、麦克风；单独建立混响样本 | 噪声抑制不等于去混响 |
| 旁人顺序或重叠说话 | 单独统计干扰语句进入结果、目标语句被删除的情况 | Voice Isolation 不是机主身份验证，也不能保证只保留机主 |

Apple 的 Voice Processing 提供回声消除、噪声抑制与自动增益控制，属于面向语音通信的组合处理；是否改善本产品的 ASR 仍需实测。处理还可能影响其他应用播放音量，实验需观察 ducking。[Apple WWDC23](https://developer.apple.com/videos/play/wwdc2023/10235/)

三个状态不能混为一个开关：

- **App 请求 Voice Processing**：采集引擎的配置；当前为关闭。
- **系统麦克风模式**：用户选择 Standard、Voice Isolation 等模式；App 不能直接代选。`preferredMicrophoneMode` 不等于当前路由实际采用的 `activeMicrophoneMode`，必须同时记录。Standard 也不等于无处理。[Apple WWDC21](https://developer.apple.com/videos/play/wwdc2021/10047/)
- **AGC**：音量增益处理；不能仅因其属性值推断整条处理链生效。读取值需与 Voice Processing 实际状态一起解释；未来比较 AGC 时单独变化这个因素。

## 最小可信实验

这是待执行方案。用户主要环境尚未确认，暂不设场景权重，也不把某一种噪声当作首要问题。

1. **先做重复基线。** 选定一台实际使用的 Mac、一个固定麦克风与系统版本，使用获准的非敏感短句，覆盖安静、普通话夹英文、数字/专名、轻声、噪声及竞争语音。固定口距、音量、摆位、ASR 资源、词库和请求配置；先重复 raw 组，估计环境和云端识别的自然波动。样本、参考文本、许可和哈希单独管理，不进入仓库或日常历史。
2. **只比较一个候选。** 首选独立实验采集器里的 Apple Voice Processing，与 raw 成对交错运行；记录实际生效状态，启用失败不能算处理组成功。处理组先固定系统模式和 AGC；需要比较 Voice Isolation 或 AGC 时另建一组，不同时更改多个因素。对真实设备路径使用固定声源和摆位重复采集，不能宣称不同现场录音是同一音频。已有 WAV 的离线对照适合可重复的本地算法，但不能代替系统真实采集、路由和回声测试。
3. **固定识别配置后比较。** 第一轮关闭语义顺滑，避免改写掩盖词错误；Default Smoothing 另用匹配参考文本复核。使用同一批句子、同一分词/归一化规则，报告各场景和设备，不只给混合平均分。授权付费请求后再上传预先批准的样本；不发送旁人未经同意的真实对话。
4. **有收益再扩设备。** 覆盖内置麦克风、常用耳麦/USB、iPhone 连续互通，以及支持范围内的系统版本和硬件。逐项检查设备消失、格式变化、睡眠、取消、快速重录、系统模式变化和其他音频播放。未测组合标为未验证，不能被一台 Mac 的结果替代。

现有 [SpeakerAccuracyEvaluator](../../Tools/SpeakerAccuracyEvaluator/main.swift)可比较已准备好的 WAV 和 ASR 参数，计算 CER、拉丁词元 WER、失败计数和请求耗时；**它没有 Voice Processing/AGC 切换、真实采集 A/B、目标说话人指标、CPU/能耗或首字/松键后延迟测量能力**。现有工具的使用与付费授权边界见[开发指南](../agents/development.md#offline-accuracy-evaluation)。实验采集器与缺少的测量工具属于后续工作，不随本策略接入产品。

## 分母、指标与采用门槛

| 维度 | 记录与比较方式 |
| --- | --- |
| 识别 | 保留每个计划样本及重复次数。CER/拉丁 WER 之外，检查数字、专名、目标词删除和干扰词插入；竞争语音需有目标/干扰参考和人工归属复核，不能把普通插入数全部称为干扰词 |
| 失败 | 启动失败、处理启用失败、无结果、供应商错误、截止观察时仍无结果分别计数。当前 evaluator 的 CER 和标签聚合只含成功样本，失败率必须以全部计划尝试为分母；不能靠丢掉困难样本提高准确率。实验截止是“尚无结果”，不改变 App 的等待语义 |
| 时延 | 实际采集另外记录按下至首帧、首字、松键至最终转录的 p50/p95，说明样本量。evaluator 的整次流式请求耗时包含音频播放时间，不等于松键后等待；失败/未完成另报，不能从耗时统计消失 |
| 资源 | 同一 Mac、相同电源/温度/后台负载下比较采集期间 CPU、内存、能耗、热状态和音频中断/缓冲耗尽；同时观察播放音量及路由变化。记录工具和测量时长，不把一次 CPU 截图当能耗结论 |
| 设备与隐私 | 固定输入设备、取消后停止、没有自动换麦或恢复旧会话、PCM 格式和有界流不变；任何新增跨供应商音频传输或日常音频落盘均不通过 |

采用门槛分两层：安全和采集不变量必须通过；质量、时延和资源预算则在重复基线完成后、查看候选结论前确定。目标问题的收益须超过基线波动，安静/轻声/数字/专名等关键场景不能出现未接受的退化，且满足预算。证据不足时保持现有默认值，不编造统一百分比或毫秒阈值。原始分母、逐场景结果和失败样本必须可追溯。

## 不变的边界与缺口

Microphone Preference 在录音按下时冻结，Input Target 在录音结束时冻结；任何处理候选都不能因输入丢失而自动改用另一支麦克风。[ADR-0008](../adr/0008-freeze-the-capture-microphone.md) 处理后的音频仍只进入豆包，Refinement Provider 只接收文本；普通 Session Record 不保存音频，安全输入框继续无正文持久化。[架构](../architecture.md)

目前缺少：用户主要场景及优先级、获准样本与参考文本、重复基线、处理组实际生效证据、设备/系统对照、资源和时延测量、质量预算及批准的付费实验范围。因此可以完成策略制定，不能宣称降噪有效、默认值应切换，或把文档完成当作音频质量验收完成。
